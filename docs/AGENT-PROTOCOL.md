# بروتوكول العمل المشترك بين المساعدين الأليّين
### CMDP — المنصة الرقمية لإدارة التعاونيات

> **الغاية:** ضمان عمل مشترك احترافي ومنظم بين المساعدين الأليّين دون تضارب أو ازدواجية أو
> فقدان للجهد — عبر أدوار واضحة، وملكية ملفات محددة، وسجلات موحدة، ودورة تدقيق إلزامية.

**الإصدار:** 1.1 — **تاريخ العمل به:** 2026-11-04

---

## 1) الأدوار والمسؤوليات

| الدور | الجهة | نطاق المسؤولية |
| --- | --- | --- |
| **المساعد المنسق** (منسق المشروع) | المساعد الألي لتطوير المنصة | تصميم وبناء الواجهات وواجهات API، مخطط قاعدة البيانات، نظام التصميم، النشر على Cloudflare Pages، صيانة عامل الشاتبوت (chatbot-worker/)، مراجعة Pull Requests وتدقيقها |
| **مساعد البيئة المحلية** (مسؤول البيئة) | المساعد الألي المشرف على بيئة التشغيل المحلية | تشغيل الباك إند وقاعدة SQLite محلياً، تنفيذ أوامر Prisma، النسخ الاحتياطي للبيانات، فحص الصحة اليومي (بما فيه صحة الشاتبوت)، إعادة ضبط البيانات التجريبية عند الطلب، توثيق حالات البيئة |

> **قاعدة ذهبية:** كل مساعد يعمل فقط داخل «منطقة ملكيته». أي عمل يخرج عنها يمر عبر
> **طلب مهمة موثق** في سجل العمل (WORKLOG).

## 2) مناطق الملكية (منع التضارب)

| المسار | المالك |
| --- | --- |
| `src/components/**`, `src/app/**`, `src/lib/**` (عدا ما يذكر أدناه), `src/hooks/**`, `src/store/**` | المساعد المنسق |
| `chatbot-worker/**` (عامل المساعد الألي) | المساعد المنسق (التعديل والنشر بحساب Cloudflare المستقل) |
| `prisma/schema.prisma` | المساعد المنسق (التعديل) + مساعد البيئة (تنفيذ `db:push`) |
| `db/` (ملفات SQLite) | **مساعد البيئة المحلية حصرياً** |
| `docs/WORKLOG.md` | مشترك — كل مساعد يضيف مدخلاته بقسمه الخاص فقط |
| `docs/CHANGELOG.md` | المساعد المنسق (يُدمج بعد كل إصدار) |
| `docs/DEPLOYMENT.md`, `docs/QA.md` | المساعد المنسق |
| `.env` | **مساعد البيئة المحلية حصرياً** (لا يُرفع أبداً إلى المستودع) |
| `scripts/**` | المساعد المنسق |
| النسخ الاحتياطية `backups/` | مساعد البيئة المحلية (خارج المستودع) |

## 3) ترقيم المهام

- الصيغة: `CMDP-###` تسلسلي (مثال: `CMDP-014`)
- بادئة نوع المهمة: `F` ميزة، `B` إصلاح، `OPS` تشغيل/بيئة، `DOC` توثيق
  (مثال: `CMDP-014/F` — إضافة وحدة التقارير)
- **لا تبدأ مهمة جديدة قبل تسجيلها في WORKLOG برقم فريد.**

## 4) دورة العمل القياسية

```
① تسجيل المهمة في WORKLOG (رقم + وصف + مالك + حالة «قيد التنفيذ»)
② التنفيذ داخل منطقة الملكية فقط
③ الفحص الذاتي (lint + tsc + اختبار المتصفح — راجع docs/QA.md)
④ تحديث حالة المهمة إلى «منجزة» مع ملخص التنفيذ والتاريخ
⑤ عند تأثير التغيير على السلوك الخارجي → إضافة بند في CHANGELOG
⑥ (اختياري للمهام الكبرى) Pull Request يراجعه المساعد الآخر قبل الدمج
```

### قواعد Git (منع تضارب الدفع)

- الفرع الرئيسي: `main` — محمي؛ لا دفع مباشراً إلا من المساعد المنسق بعد الفحص.
- مساعد البيئة المحلية يعمل على فرع `ops/local-env` عند تعديل أي ملف مشترك،
  ويطلب الدمج عبر PR يراجعه المساعد المنسق.
- رسائل الالتزام بالعربية مع رقم المهمة: `CMDP-014/F: إضافة وحدة التقارير`.
- **قبل كل دفع:** `git pull --rebase` ثم التأكد من نجاح `npm run lint`.

## 5) قنوات التنسيق

1. **WORKLOG.md** — القناة الرسمية الوحيدة لتعقب المهام والحالات.
2. **CHANGELOG.md** — سجل ما يتغير بين الإصدارات (للمستخدم النهائي).
3. **طوابير الفحص:** قبل تسليم أي مهمة تُرفق نتائج بوابات الجودة (انظر QA.md):
   `lint ✓ / tsc ✓ / browser ✓ / responsive ✓`

## 6) مهام مساعد البيئة المحلية — التشغيل المرجعي

عند استلام المستودع أول مرة أو بعد كل سحب:

```bash
npm install               # تثبيت الاعتماديات
cp .env.example .env      # عنوان قاعدة SQLite
npm run db:push           # مزامنة المخطط مع قاعدة البيانات
npm run accounts:create   # الحسابات الحقيقية (المالك + طقم اختبار الأدوار)
npm run dev               # تشغيل الباك إند على المنفذ 3000
```

> **مهم (منذ 1.3.0):** القاعدة الحقيقية لا تُزرع بـ `npm run seed` (بيانات
> العرض بكلمة مرور مكشوفة) — تُدار بحسابات حقيقية عبر `npm run accounts:create`:
> يطبع بيانات الدخول مرة واحدة (كلمات مرور عشوائية قوية) ثم تُغيَّر من وحدة
> المستخدمين. الخيارات: `--owner-only` (المالك فقط) و`--purge-demo` (حذف
> حسابات العرض القديمة إن وُجدت) و`--password "..."` (كلمة مرور مخصصة للمالك).
> أمر `npm run seed` يبقى متاحاً لبيئات التطوير والتجريب فقط.

**الفحص الدوري (يومياً أو عند كل تحديث):**

| الفحص | الأمر | النتيجة المتوقعة |
| --- | --- | --- |
| صحة API | `curl http://localhost:3000/api/cooperatives` | HTTP 200 + مصفوفة JSON |
| صحة الشاتبوت | `curl https://cmdp-assistant.tkchouika-cmdp.workers.dev/` | `{"ok":true,...}` |
| صحة قاعدة البيانات | `npx prisma db pull --print` | لا أخطاء |
| النسخ الاحتياطي | نسخ `db/custom.db` إلى `backups/` بتاريخ اليوم | ملف .db جديد |
| الأخطاء الحية | مراقبة سجل `npm run dev` | خلو من stack traces |

**عند تعذر الوصول للمنصة المنشورة (cmdp.pages.dev) إلى الباك إند المحلي:**
تأكد من إدخال عنوان الخادم المحلي (مثال `http://192.168.1.10:3000`) في
**الإعدادات ← الاتصال بالباك إند المحلي** — وتأكد من أن الباك إند يعمل ويسمح بـ CORS
(مفعَّل افتراضياً في جميع مسارات `/api/*`).

## 7) آلية حل التضارب

1. من واجه تضارباً في Git لا يتجاوز ملفات ملكيته → يحله مباشرة ويوثق ذلك.
2. التضارب في الملفات المشتركة (WORKLOG) → الدمج التسلسلي حسب التاريخ؛ الأقدم يبقى
   والأحدث يُضاف تحته في قسم المساعد المعني.
3. خلاف في القرار المعماري → يُفتح بند «قرار معلق» في WORKLOG بوسم `[DECISION]`
   ويُحسم بمراجعة الطرفين خلال 48 ساعة.

## 8) مرجع أدوار المنصة (منذ 1.1.0)

> هذه أدوار **مستخدمي المنصة** (وليست أدوار المساعدين الأليّين أعلاه).
> المصدر الوحيد للحقيقة: `src/lib/permissions.ts`.

| الدور | صلاحياته |
| --- | --- |
| **سوبر أدمين** (مالك المنصة) | جميع الصلاحيات — الوحيد الذي يدير حسابات الأدمن |
| **أدمن منصة** | إنشاء تعاونية والمصادقة على تسجيلها؛ تسجيل/المصادقة على مستخدمين كوأدمن (رؤساء وأعضاء مسيرين)؛ إنشاء أعضاء ومتعاقدين |
| **كوأدمن — رئيس تعاونية** | كل صلاحيات التعاونية + تفويض المهام للمسيّرين + المصادقة على الانخراطات وإنشاء الحسابات داخلها |
| **كوأدمن — عضو مسير** | تسيير التعاونية (أعضاء/جمعات/مالية/وثائق/فرص) + المصادقة على المستخدمين داخلها |
| **مستخدم — عضو غير مسير** | الاطلاع والمشاركة في الجموع العامة والتصويت وكل حقوق المنخرط حسب القانون 112.12 |
| **مستخدم — متعاقد** | الاطلاع حصراً على ما يصرح به الرئيس أو أحد المسيّرين |

**حسابات الاختبار الحقيقية** (منذ 1.3.0 تُنشأ بـ `npm run accounts:create` بكلمات مرور قوية تُطبع مرة واحدة): طقم كامل — المالك + رئيس + مسير + عضو + متعاقد. بيانات العرض القديمة (`cmdp2026`) لم تعد معروضة في واجهة الدخول إطلاقاً؛ `npm run seed` يبقى لبيئات التجريب المعزولة فقط.

## 9) السرية والأمان

- لا تُرفع أبداً: `.env`، مفاتيح API، رموز GitHub/Cloudflare، ملفات `db/*.db`.
- أي واقعة أمنية (تسرب رمز مثلاً) تُوثق فوراً بوسم `[SECURITY]` في WORKLOG مع خطوات المعالجة.

## 10) ميثاق مساعد البيئة المحلية — توجيهات صارمة (منذ 1.3.1)

> هذا الميثاق ملزم بالكامل. أي إخلال به يُوثَّق بوسم `[INCIDENT]` في WORKLOG.
> المبدأ الحاكم: **حماية المكتسبات أولاً** — بيئة تعمل ببيانات ناقصة خير من بيئة
> معطوبة ببيانات مفقودة.

### أ) الواجبات الحصرية (ولا شيء غيرها)

| # | الواجب | الأمر/الإجراء | الدورية |
| --- | --- | --- | --- |
| 1 | تشغيل الباك إند المحلي | `npm run dev` (منفذ 3000) وإبقاؤه حياً | عند كل طلب تشغيل |
| 2 | مزامنة المخطط بعد السحب | `npm run db:push` — **فقط** إن أشار WORKLOG/CHANGELOG لتغيير في `prisma/schema.prisma` | بعد كل سحب يغيّر المخطط |
| 3 | الفحص الصحي اليومي | جدول §6 (API + الشاتبوت + القاعدة + السجل) | يومياً |
| 4 | النسخ الاحتياطي | نسخ `db/custom.db` إلى `backups/YYYY-MM-DD.db` قبل أي أمر يمسّ المخطط، ويومياً | قبل كل مخطط + يومياً |
| 5 | إنشاء الحسابات الحقيقية عند الطلب | `npm run accounts:create` (أو `--owner-only`) | عند الطلب فقط |
| 6 | توثيق حالات البيئة | إضافة بند مؤرخ في WORKLOG بقسم مساعد البيئة | عند كل واقعة |

### ب) المحظورات الصريحة (قائمة سوداء)

1. **يُمنع تعديل أي ملف خارج ملكيتك**: لا `src/**`، لا `android/**`، لا `.github/**`،
   لا `chatbot-worker/**`، لا `public/**`. مالكها المساعد المنسق حصراً.
2. **يُمنع `git push` و`git commit` نهائياً** — حتى داخل ملفات ملكيتك؛ التوثيق يمر
   عبر WORKLOG بطلب مهمة موثق للمساعد المنسق.
3. **يُمنع تشغيل الأوامر المدمرة** إلا بطلب صريح موثق من المالك في WORKLOG بوسم
   `[DATA-RESET]`: `prisma migrate reset`، حذف `db/custom.db`، `db:push` مع فقد بيانات
   دون نسخة احتياطية مسبقة.
4. **يُمنع حذف أو تعطيل الحسابات الحقيقية** (المالك، طقم الاختبار، حسابات رؤساء
   التعاونيات) — ولو بدا أنها «بيانات تجريبية».
5. **يُمنع تعديل كلمات المرور** لأي حساب قائم؛ تصفير كلمة المرور يتم من واجهة
   المستخدمين من طرف المخوّل فقط.
6. **يُمنع فتح المنفذ 3000 على الشبكة العمومية** بلا نفق موثق (Cloudflare Tunnel
   موجود مسبقاً) ولا تنشر أي عنوان أو رمز في مكان عام.

### ج) حالات طبيعية — لا تُعالج ولا تُبلَّغ كأعطال

- **ظهور حسابات العرض/الاختبار في واجهة الدخول أو قوائم المستخدمين بالبيئة المحلية
  أمر طبيعي ومتوقع**: البيئة المحلية للتشغيل والاختبار. لا تحذفها، ولا «تنظفها»،
  ولا تعدّل الواجهة لأجلها — إزالتها من الواجهة قرار تصميمي اتُّخذ في 1.3.0 على
  مستوى المنسق، وحسابات قاعدة الاختبار المحلية تبقى لاختبار المالك.
- زر «استكشاف المنصة في وضع العرض» في صفحة الدخول عند توقف الباك إند سلوك مقصود
  (وضع عرض بلا حسابات) — ليس عطلاً.
- بطء أول طلب بعد الإقلاع (تجميع Next.js) طبيعي؛ انتظر ثم أعد الفحص قبل الإبلاغ.
- اختلاف عدد السجلات بين بيئة محلية وأخرى طبيعي (قواعد منفصلة) — لا «مزامنة» يدوية.

### د) بروتوكول الترقية بعد كل سحب (SOP)

1. `git pull` ثم قراءة أحدث بندين في WORKLOG وCHANGELOG.
2. إن ذُكر تغيير مخطط: نسخة احتياطية فورية، ثم `npm run db:push`، ثم فحص صحي كامل.
3. إن لم يُذكر: `npm install` (إن تغيّر `package.json`) ثم إعادة تشغيل الخادم فقط.
4. توثيق النتيجة بسطر واحد في WORKLOG: التاريخ + رقم الإصدار + «تمت الترقية بلا
   أخطاء» أو تفاصيل الخطأ **دون أي محاولة إصلاح خارج الملكية**.

### هـ) التصعيد عند العطل

| الحالة | الإجراء الفوري |
| --- | --- |
| الخادم لا يقوم | قراءة آخر 50 سطراً من السجل؛ إن كان الخطأ في الكود → تصعيد للمساعد المنسق بوسم `[BUG]` في WORKLOG مع السجل |
| قاعدة البيانات معطوبة | استرجاع آخر نسخة من `backups/` — **لا reset أبداً** — ثم تصعيد |
| فشل `db:push` | إيقاف فوري، لا `--accept-data-loss` إضافية، تصعيد بوسم `[SCHEMA]` |
| فقدان بيانات مشتبه | إيقاف الخادم (تجميد الوضع)، نسخة احتياطية من الملف الحالي، تصعيد عاجل |
